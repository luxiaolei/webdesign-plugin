# Competitive landscape

The current gap is not another component gallery. The useful product is a small control plane that turns a brief into a coherent visual direction, then makes source and acceptance evidence travel with the implementation.

| Source | Strongest job | What it does not solve | Role here |
| --- | --- | --- | --- |
| MotionSites MCP | Prompt-level visual direction | It does not own the target project's tokens or QA | Research input |
| React Bits | Animated React source | It is a component source, not a page narrative | Motion layer |
| Uiverse | Fast open-source UI fragments | Quality and style vary by item | Micro-interaction search |
| Aceternity UI | Landing blocks, templates, registry/MCP | Free and paid material are mixed | Page structure and effects |
| Screenshot to Code | Screenshot/Figma/recording to code | It can approximate without a source ledger | Permitted reconstruction |
| OpenPage | JSON-first visual builder | It is a builder, not a multi-source research workflow | Optional assembly target |
| Loupe | Live-render editing and visual verification | Current upstream target is Windows | QA loop reference |
| CopyWeb / Clonesite | Commercial URL cloning | Licensing and project integration remain separate | Benchmark only |
| Google Design MCP / Design Systems MCP | Agent-readable design-system guidance | They do not provide this project's brand direction | Rules and accessibility |

The plugin's smallest defensible advantage is the handoff between these layers: source discovery → license ledger → tokens and page story → owned implementation → browser acceptance. A single MCP aggregator can be added later, but it should not hide which upstream source supplied a component or what terms apply.
